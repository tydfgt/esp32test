## 4. 墨水屏驱动核心概念

### 4.1 初始化模式

```cpp
EPD_5in83_V2_Init();        // 标准全刷
EPD_5in83_V2_Init_Fast();   // 快速全刷（图像可能有轻微残影）
EPD_5in83_V2_Init_Part();   // 局部刷新模式
EPD_5in83_V2_Init_4GRAY();  // 4 级灰度
```

### 4.2 标准显示流程

```
Init → 创建画布 → 绘制 → Display → Sleep
```

```cpp
// 全屏刷新
EPD_5in83_V2_Init();
Paint_NewImage(buf, 648, 480, 0, WHITE);
Paint_SelectImage(buf);
// ... 绘图 ...
EPD_5in83_V2_Display(buf);
EPD_5in83_V2_Sleep();

// 局部刷新（只更新指定矩形区域）
EPD_5in83_V2_Init_Part();
Paint_NewImage(smallBuf, w, h, 0, WHITE);
// ... 在小画布上绘图 ...
EPD_5in83_V2_Display_Partial(smallBuf, x0, y0, x1, y1);
EPD_5in83_V2_Sleep();
```

### 4.3 动画高速显示流程（GIF 项目）

不需要每次 Init/Sleep，只在 setup 时初始化一次，然后循环调用 Display_Partial：

```cpp
void setup() {
    EPD_5in83_V2_Init();
    EPD_5in83_V2_Clear();       // 全刷清屏，建立基底
    EPD_5in83_V2_Init_Part();   // 只初始化一次
}

void loop() {
    // 直接 Display_Partial，无需重复 Init_Part / Sleep
    fastPartial(gGifFrames[idx]);  // 约 476ms/帧
}
```

### 4.4 关键：Init 和 Sleep 必须配对

- 每次 `Init_*` 后，操作完必须 `Sleep`
- 切换 Init 模式（如从 `Init` 切到 `Init_Part`）需要先 Sleep 再重新 Init
- 长时间只做局部刷新会产生残影，需要定期全刷

## 5. 像素格式辨析（重要！）

项目中存在**两套像素约定**，容易混淆导致反色/空白：

### 5.1 Paint API / SPI 数据格式（图像数据）

用于 `EPD_5in83_V2_Display()` / `Display_Partial()` 传入的图像缓冲区：

- **1 bit = 白色像素**
- **0 bit = 黑色像素**
- MSB first，按行存储

```python
# convert_image.py / convert_gif_to_c.py 中的编码
if px == 255:       # 白像素
    b |= (1 << (7 - bit))   # bit=1
# 黑像素 bit 保持 0
```

验证：`Paint_Clear(WHITE)` 填充 `0xFF`（全1=白），`Paint_Clear(BLACK)` 填充 `0x00`（全0=黑）。

### 5.2 字模数据格式（Font bitmap）

用于 `Paint_DrawStringCN()` 传入的字模点阵：

- **1 bit = 前景色（黑色笔画）**
- **0 bit = 背景（透明/白色）**

```python
# 字模生成脚本中的编码
if pixel <= 128:    # 深色 → 笔画
    b |= (1 << (7 - bit))   # bit=1
```

Paint API 内部在绘制字符串时会自动反转字模数据，所以两套约定不冲突。

### 5.3 一句话总结

| 数据类型 | 1-bit 含义 | 0-bit 含义 |
|----------|-----------|-----------|
| 图像缓冲区（Display 传入） | 白 | 黑 |
| 字模点阵（Font 传入） | 黑（笔画） | 白（背景） |

**生成图像 C 数组时**：白=1，黑=0（与 SPI 数据一致）  
**生成字模 C 数组时**：黑=1，白=0（与 Font 约定一致）

## 6. SPI 性能优化

### 6.1 背景

驱动库原版使用 `digitalWrite()` 进行 bit-bang SPI，每字节需要 8 次 `digitalWrite`，每次约 1-2μs。对于 29KB 的帧数据，仅 SPI 传输就需要约 200-400ms。

### 6.2 优化方案：ESP32 寄存器直操作

ESP32 的 GPIO 寄存器可直接写入，比 `digitalWrite()` 快 10-50 倍：

```cpp
#include "soc/gpio_reg.h"

// 预计算位掩码
static const uint32_t SCK_MASK  = 1UL << EPD_SCK_PIN;   // GPIO 13
static const uint32_t MOSI_MASK = 1UL << EPD_MOSI_PIN;  // GPIO 14
static const uint32_t CS_MASK   = 1UL << EPD_CS_PIN;    // GPIO 15
static const uint32_t DC_MASK   = 1UL << EPD_DC_PIN;    // GPIO 27

// 写1（拉高）
WRITE_PERI_REG(GPIO_OUT_W1TS_REG, mask);
// 写0（拉低）
WRITE_PERI_REG(GPIO_OUT_W1TC_REG, mask);
```

### 6.3 已实现的优化（在 DEV_Config.cpp 和 epaper_gif.ino 中）

| 优化项 | 方法 | 效果 |
|--------|------|------|
| 单字节传输 | `WRITE_PERI_REG` 替代 `digitalWrite` | SPI 速度提升 10-50× |
| 批量传输 | `DEV_SPI_Write_nByte` 只切换一次 CS | 减少 CS 切换开销 |
| 帧内批量传输 | `sendDataBurst()` 整帧数据一次 CS | 进一步减少开销 |
| 紧凑忙等待 | `while(!digitalRead(BUSY))` 替代 10ms 轮询 | 减少 busy wait 余量 |
| 减少不必要延时 | TurnOnDisplay 100ms→1ms | 减少固定延时 |

### 6.4 性能数据

| 版本 | 每帧耗时 | fps | 说明 |
|------|---------|-----|------|
| 原始（Init+Sleep+dw SPI） | 1491ms | 0.67 | 每帧都 Init_Part + Sleep + digitalWrite |
| 去掉每帧 Init/Sleep | 907ms | 1.1 | 只初始化一次 |
| 寄存器 SPI | 531ms | 1.9 | WRITE_PERI_REG 替代 digitalWrite |
| 全部优化 | 476ms | 2.1 | 批量传输 + 紧凑 busy wait |

**极限**：~476ms 中的 ~400ms 是 e-paper IC 的物理刷新时间（busy wait），无法通过软件优化突破。理论最高约 2-2.5fps。

### 6.5 注意事项

- GPIO 0-31 用 `GPIO_OUT_W1TS_REG` / `GPIO_OUT_W1TC_REG`
- GPIO 32-39 用 `GPIO_OUT1_W1TS_REG` / `GPIO_OUT1_W1TC_REG`（本项目的引脚都在 0-31 范围内）
- 需要 `#include "soc/gpio_reg.h"`
- 寄存器操作不会检查引脚是否已设为输出模式，需确保先 `pinMode(pin, OUTPUT)`

## 7. 自定义中文字模

### 7.1 为什么需要

库自带的 `Font12CN` / `Font24CN` 仅含约 20 个汉字（微雪电子你好…），完全不实用。

### 7.2 字模格式

```c
typedef struct {
    unsigned char index[3];   // UTF-8 编码的 3 字节
    const char matrix[164];   // 点阵数据 (MAX 41×32/8)
} CH_CN;

typedef struct {
    const CH_CN *table;
    uint16_t size;
    uint16_t ASCII_Width;     // ASCII 步进宽度 (通常为 Width/2)
    uint16_t Width;
    uint16_t Height;
} cFONT;
```

### 7.3 像素格式

- **1 bit = 前景色（黑色笔画）**
- **0 bit = 背景（透明/白色）**
- 每字节 8 像素，MSB first，按行存储
- ⚠️ 与图像缓冲区格式相反！见[第5节](#5-像素格式辨析重要)

### 7.4 生成脚本要点

```python
from PIL import Image, ImageFont, ImageDraw

font = ImageFont.truetype("/usr/share/fonts/truetype/wqy/wqy-microhei.ttc", 32)

for ch in "广州增城晴多云阴...":
    img = Image.new("L", (96, 96), 255)     # 3x 画布抗锯齿
    draw = ImageDraw.Draw(img)
    draw.text((centered_x, centered_y), ch, font=font, fill=0)
    img = img.resize((32, 32), Image.LANCZOS)
    # 提取点阵（黑→1, 白→0）
    for y in range(32):
        for xb in range(4):  # 32/8=4 bytes per row
            b = 0
            for bit in range(8):
                if img.getpixel((xb*8+bit, y)) <= 128:
                    b |= (1 << (7 - bit))
            bitmap.append(b)
    # UTF-8 索引
    utf8 = list(ch.encode('utf-8'))
    while len(utf8) < 3: utf8.append(0)
```

### 7.5 常用字体

| 路径 | 风格 |
|------|------|
| `/usr/share/fonts/truetype/wqy/wqy-microhei.ttc` | 文泉驿微米黑（无衬线） |
| `/usr/share/fonts/opentype/noto/NotoSansCJK-*.ttc` | Noto Sans CJK |

## 8. 图片与 GIF 动画显示

### 8.1 单张图片（PNG → C 数组）

```
PNG → 灰度 → 缩放到目标尺寸 → Floyd-Steinberg 抖动 → 1-bit C 数组
```

工具：`dev-tools/convert_image.py`

```bash
/usr/bin/python3 convert_image.py input.png ImageData 648 480
```

### 8.2 GIF 动画（多帧）

工具：`~/esp32/projects/epaper_gif/convert_gif_to_c.py`

```bash
/usr/bin/python3 ~/esp32/projects/epaper_gif/convert_gif_to_c.py <gif路径> <输出目录>
```

**处理流程**：

1. 提取 GIF 所有帧（正确处理 delta 帧合成：`paste(frame_rgba, mask=alpha)` 到白底）
2. 等比缩放到屏幕宽度（648px），只存储内容区域（不含白边）
3. Floyd-Steinberg 抖动转 1-bit
4. 生成 `GifFrames.h`（声明 + 常量宏）和 `GifFrames.cpp`（PROGMEM 数组）
5. 保存首帧预览 PNG

**生成参数示例**（480×270, 40帧 GIF）：

| 参数 | 值 |
|------|---|
| 缩放后尺寸 | 648×364 |
| Y 偏移（居中） | 58 |
| 每帧字节 | 648/8 × 364 = 29,484 |
| 40 帧总计 | 1,179,360 bytes (1,151.7 KB) |
| Flash 占用 | 47% (huge_app 分区 3MB) |

### 8.3 GIF 动画固件架构

```cpp
// epaper_gif.ino 核心逻辑

void setup() {
    EPD_5in83_V2_Init();
    EPD_5in83_V2_Clear();       // 全刷清屏
    EPD_5in83_V2_Init_Part();   // 只初始化一次局部刷新
}

void loop() {
    fastPartial(gGifFrames[frameIdx]);   // ~476ms/帧
    frameIdx = (frameIdx + 1) % GIF_FRAME_COUNT;
    // 每 N 轮全刷清残影
}
```

`fastPartial()` 是绕过驱动的优化实现：直接用寄存器操作 SPI，批量传输帧数据，紧凑 busy wait。

### 8.4 残影管理

局部刷新会累积残影。GIF 项目每 5 轮（约 5×40×0.5s ≈ 100秒）全刷清一次。可通过 `CYCLES_BEFORE_CLEAR` 调整：
- 值更小：残影更少，但全刷白闪更频繁
- 值更大：动画更流畅，但残影会逐渐明显

## 10. 全刷 vs 局部刷新

| | 全屏刷新 | 局部刷新 |
|------|---------|---------|
| 函数 | `EPD_5in83_V2_Display()` | `EPD_5in83_V2_Display_Partial()` |
| Init | `EPD_5in83_V2_Init()` | `EPD_5in83_V2_Init_Part()` |
| 速度 | 慢（~2-3秒） | 快（~0.3-0.5秒） |
| 残影 | 无 | 会累积 |
| 用途 | 初始显示、清残影 | 每秒更新时间、动画 |

### 局部刷新坐标对齐

- X 坐标最好是 8 的倍数（Display_Partial 内部会做 X/8 对齐）
- 全刷和局部刷的同一元素必须在**相同坐标**绘制，否则偏移/重影

### 局部刷新的 Display_Partial 坐标

```cpp
EPD_5in83_V2_Display_Partial(buf, Xstart, Ystart, Xend, Yend);
// (Xstart, Ystart) = 左上角像素坐标
// (Xend, Yend) = 右下角像素坐标（不含，即 [Xstart, Xend) ）
```

内部会自动将 X 坐标除以 8 转为字节列。

## 11. 踩坑记录

### 11.1 Linux 文件名大小写

`#include "imagedata.h"` 但文件是 `ImageData.h` → **编译失败**。
Arduino CLI 在 Linux 上严格区分大小写。

### 11.2 Arduino.h 大小写

字模生成脚本中写 `<arduino.h>` → 编译失败。
正确写法：`<Arduino.h>`（大写 A）。

### 11.3 像素格式反转（最常见！）

图像数据和字模数据使用**相反的像素约定**：
- 图像缓冲区：1=白，0=黑
- 字模点阵：1=黑（笔画），0=白（背景）

搞反会导致反色或空白。详见[第5节](#5-像素格式辨析重要)。

### 11.4 5.83 寸必须用 V2 驱动

官方 Wiki 明确：5.83inch → `epd5in83_V2-demo`。
分辨率 648×480，与老款 600×448 不兼容。

### 11.5 中文字库不全

库自带 `Font24CN` 只有 20 个汉字。必须自建字模。

### 11.6 天气 API 的 temperature 是数字

用 `doc["temperature"] | -999.0f` 获取 float，不能用 `.as<const char*>()`。

### 11.7 ESP-IDF 虚拟环境屏蔽 PIL

`python3` 被 ESP-IDF 劫持，PIL 不可用。图片/字模脚本必须用 `/usr/bin/python3`。

### 11.8 局部刷新必须定期全刷

连续局部刷新 5-10 分钟后会产生明显残影。时钟项目每 10 分钟全刷一次。

### 11.9 画布 buffer 复用

每次 `Paint_NewImage` 前不需要 `free` 旧 buffer，复用即可。但注意不要越界。

### 11.10 串口波特率

ESP32 烧录后串口默认 115200。用 `arduino-cli monitor -c baudrate=115200`。

### 11.11 秒刷新频率不准（只显示偶数秒）

`delay(980)` + 局部刷新耗时 ≈ 1.2~1.5 秒/轮，会导致奇数秒被跳过。

**正确做法**：用 `delay(50)` 高频轮询 + `partialTime()` 内部判断秒是否变化：

```cpp
void loop() {
    partialTime();  // 内部 if (sec == g_lastSec) return;
    delay(50);
}
```

### 11.12 天气 JSON 字段类型

uapis.cn API 中 `temperature` 是 `float`、`humidity` 是 `int`，不是字符串：

```cpp
float t = doc["temperature"] | -999.0f;
int hum  = doc["humidity"] | -1;
```

### 11.13 GIF 帧合成需处理 alpha

GIF 的后续帧可能是 delta 帧（只包含变化区域），直接 `convert("L")` 会丢失内容。
必须先 `convert("RGBA")` 然后 `paste(frame_rgba, mask=alpha)` 到白底。

### 11.14 动画项目必须用 huge_app 分区

40 帧 × 29KB/帧 ≈ 1.15MB，默认分区的 ~1.2MB app 空间可能不够。
使用 `PartitionScheme=huge_app` 获得 3MB app 分区。

### 11.15 ESP32 PROGMEM 数据可直接传给 Display_Partial

ESP32 的 flash 是内存映射的，`const ... PROGMEM` 数组可直接作为指针传给驱动函数，
不需要先 `memcpy` 到 RAM 缓冲区。

### 11.16 SPI bit-bang 速度是动画瓶颈

原始 `digitalWrite` bit-bang 约 400ms/29KB。改用 `WRITE_PERI_REG` 寄存器直操作后降至约 70ms。
但 e-paper IC 的物理刷新时间（busy wait ~400ms）是硬件极限，无法通过软件突破。

## 附录 B：Display_Partial 协议参考

`fastPartial()` 在 epaper_gif.ino 中的实现，可用于其他需要高速局部刷新的场景：

```cpp
// 核心协议序列
sendCmd(0x50); sendData(0xA9); sendData(0x07);  // VCOM 设置
sendCmd(0x91);                                     // 进入 partial 模式
sendCmd(0x90);                                     // 设置 partial 窗口
// 8 字节坐标数据：Xstart_hi, Xstart_lo, Xend_hi, Xend_lo, Ystart_hi, Ystart_lo, Yend_hi, Yend_lo
sendData(0x01);                                    // 窗口设置完成
sendCmd(0x13);                                     // 写入图像数据
sendDataBurst(img, imgCount);                      // 批量传输
sendCmd(0x12);                                     // DISPLAY REFRESH
delayMicroseconds(200);
waitBusy();                                        // 等待 IC 完成
sendCmd(0x92);                                     // 退出 partial 模式
```
